## 4. 저장·인증 방식

| 데이터 | 현재 저장 방식 |
|---|---|
| 관광·지역·유형 | MySQL `attractions`, `sidos`, `guguns`, `contenttypes` |
| 회원·복구 답변 | MySQL `members`, 비밀번호와 답변을 PBKDF2 해시로 저장 |
| 로그인 | 서버 HttpSession, 기본 20분 |
| 여행계획·방문 순서 | MySQL `trip_plans`, `trip_plan_places`, 함께 저장·롤백 |
| 공지·게시글·댓글 | MySQL `posts`, `comments`, 서버 권한 검사 |
| Hotplace | MySQL `travel_records`, 로그인한 본인 기록만 조회 |
| 업로드 사진 | 회원별 서버 폴더, DB에는 파일명, 인증한 소유자만 파일 조회 |

## 5. 구현 완료로 보지 않는 범위

- 실제 도로 기반 경로 탐색, 날짜별 일정 편집, 저장된 여행계획 수정
- Hotplace 공개 공유, 다른 회원의 기록 열람
- 이메일·문자 인증 방식의 비밀번호 재설정
- 관광지 전화번호·홈페이지·개요를 표시하는 별도 상세 화면
- 뉴스·날씨·추천 사진·일출·일몰·전기차 충전소 연동
- 별도 CSRF 토큰, 요청 횟수 제한, 대규모 부하·운영 가용성 검증

현재 구현과 실제 화면은 [README](../README.md), 검증 내용은 [verification.md](verification.md)를 기준으로 합니다. 이전 단계의 TourAPI·파일 직렬화·localStorage 기반 설계는 현재 DB 저장 방식을 설명하지 않습니다.
